# Mastigias — Subagent Execution & Implementation Guide

This guide establishes the execution rules, interface contracts, phase gates, and prompt templates for implementing the **Mastigias** Android tag editor using sequential autonomous AI subagents.

---

## 1. Executive Summary & Strategy

Attempting to run multiple subagents **in parallel** on `MASTIGIAS_SPECIFICATION.md` creates severe merge conflicts (monolithic `:app` module, shared `build.gradle.kts`, `AndroidManifest.xml`, Hilt modules, and navigation graphs) and leads to divergent implementations of missing domain interfaces.

**Sequential relay execution** solves these bottlenecks:
1. **Zero Merge Conflicts**: Only one subagent touches configuration, DI, or source files at a time.
2. **Self-Documenting Code**: Concrete Kotlin interfaces written by earlier subagents are read directly from disk by later subagents.
3. **Progressive Verification**: Each subagent must pass compilation and test gates before passing control to the next subagent.
4. **Architectural Consistency**: Clean Architecture boundaries are established once in Milestone 0 and preserved across all subsequent turns.

---

## 2. Universal Subagent Operating Rules

Every subagent working on this repository MUST strictly follow these rules:

1. **Read Before Writing**:
   Never assume file contents or re-invent interfaces. Always `read` the existing files generated by prior subagents before writing new classes or wiring dependencies.
2. **Preserve Clean Architecture Invariants**:
   * `domain/` contains pure Kotlin only (no Android framework imports, no Compose, no Room, no `data/` layer imports).
   * Repositories and engines are exposed to domain via interfaces (`MusicRepository`, `TagEngine`, `PreferencesRepository`).
   * Concrete implementations belong strictly in `data/`.
3. **No Batch Failures / Strict Stop Gates**:
   Never mark a milestone or task complete if compilation fails, tests fail, or files are left in a broken state. Fix errors within the subagent turn.
4. **NDK / Native Fallback Rule**:
   If the execution environment lacks Android NDK r26+ or cannot reach external URLs for CMake `FetchContent` (TagLib source), the native bridge MUST be provided with a functional JVM mock/stub implementation alongside the C++ files so that pure Kotlin builds (`compileDebugKotlin`) do not stall.
5. **Atomic Commits & Minimal Edits**:
   Keep modifications scoped strictly to the assigned milestone files. Do not preemptively author skeleton files for future milestones unless explicitly required for DI bindings.

### 3.4 Clean Architecture Fix for `BatchWriteMetadataUseCase.kt`
`BatchWriteMetadataUseCase` must inject `MusicRepository`, NOT `TrackDao` or `ScopedStorageManager`:
```kotlin
package now.link.mastigias.domain.usecase

import kotlinx.coroutines.flow.Flow
import kotlinx.coroutines.flow.flow
import now.link.mastigias.domain.model.*
import now.link.mastigias.domain.repository.MusicRepository
import now.link.mastigias.ui.editor.FieldEditState
import javax.inject.Inject

data class BatchProgress(
    val current: Int,
    val total: Int,
    val currentTitle: String,
    val failedIds: List<Long> = emptyList()
)

class BatchWriteMetadataUseCase @Inject constructor(
    private val musicRepository: MusicRepository
) {
    operator fun invoke(
        trackIds: List<Long>,
        fieldEdits: Map<TagField, FieldEditState>,
        artworkData: ArtworkData?,
        isArtworkBatchEnabled: Boolean,
        removeArtwork: Boolean
    ): Flow<BatchProgress> = flow {
        val total = trackIds.size
        val failedIds = mutableListOf<Long>()

        val updatedFields = fieldEdits
            .filter { (field, state) -> state.isEnabledInBatch && field.category != TagCategory.LYRICS }
            .mapValues { it.value.value }

        val toDelete = updatedFields.filter { it.value.isBlank() }.keys
        val toUpdate = updatedFields.filter { it.value.isNotBlank() }

        val batchPatch = TagPatch(
            updatedFields = toUpdate,
            deletedFields = toDelete,
            updatedArtwork = if (isArtworkBatchEnabled && !removeArtwork) artworkData else null,
            removeArtwork = if (isArtworkBatchEnabled) removeArtwork else false
        )

        val tracks = musicRepository.getTracksByIds(trackIds).associateBy { it.id }

        for ((index, trackId) in trackIds.withIndex()) {
            val track = tracks[trackId]
            val title = track?.title ?: "Track #$trackId"
            emit(BatchProgress(current = index + 1, total = total, currentTitle = title, failedIds = failedIds))

            if (track == null) {
                failedIds.add(trackId)
                continue
            }

            val result = musicRepository.writeTrackMetadata(track.id, batchPatch)
            if (result.isFailure) {
                failedIds.add(trackId)
            }
        }

        emit(BatchProgress(current = total, total = total, currentTitle = "Complete", failedIds = failedIds))
    }
}
```

## 6. Error Recovery & Escalation Protocols

* **If a subagent encounters missing symbols**: It must search the codebase (`rg` or `find`) before assuming an interface exists. If missing, it must implement it according to `MASTIGIAS_SPECIFICATION.md` rather than mocking or bypassing it.
* **If CMake/FetchContent fails due to network or NDK**: Implement `TagLibEngineImpl` with graceful JVM stub fallbacks so pure Kotlin compilation (`compileDebugKotlin`) remains unblocked.
* **If Hilt triggers duplicate binding errors**: Check `RepositoryModule.kt` and `EngineModule.kt` to ensure `@Binds` and `@Provides` are not duplicating singleton registrations.
